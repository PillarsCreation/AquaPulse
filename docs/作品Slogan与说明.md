## 二、问题

山洪与山体滑坡是我国伤亡最频繁的灾害类型之一，但基层防汛长期存在四个结构性难题：

1. **来得快，判得慢。** 一条沟谷从发现险情到洪峰抵达往往只有十几分钟，而县级指挥部要同时盯十几个乡镇、上百个村组，靠人工会商研判，平均需要 30 分钟以上才能定下"转移谁、派谁去、走哪条路"。
2. **预警发得出，群众看不懂。** 传统预警是专业术语堆砌的水文数据，村民看不明白，不知道该不该走、往哪走。
3. **断网即失联。** 极端天气下公网基站断电，村民求救无门，指挥部的指令也下不去，最危险的时刻恰恰是通信最差的时刻。
4. **灾后统计拖太久。** 农田定损靠人跑田、填表、层层汇总，一个县往往要 7 天才能出结果，直接影响救灾与理赔进度。

---

## 三、方案

AquaPulse 用"测-报-预-救-评"五个环节串成一条 AI 驱动的闭环：

- **测**：接入雨量站、雷达、卫星多源数据，一并纳入地形坡度、土壤类型、人口分布。
- **报**：按国标自动生成红/橙/黄/蓝四级预警，同时产出两个版本——给村民的**通俗版**和给指挥部的**专业溯源版**。
- **预**：核心是**八步山洪推演引擎**——降雨输入 → 产汇流 → 沟道演进 → 淹没分析 → 风险评估 → 分级预警 → 转移任务 → 反馈校正。8 秒跑完传统需要数小时的水文研判，洪峰到达误差 ±15 分钟、淹没范围误差 ±12%。
- **救**：村民一键 SOS 后，**AI 智能派单**自动检索应急预案、调用推演模型、匹配最近救援队伍、规划绕开深水点的路线、生成任务包直达救援人员手机；公网中断时自动改走**北斗短报文**，做到"断网不断联"。
- **评**：结合淹没水深与无人机正射影像 AI 识别受淹农田，定损周期从 7 天压缩到 2 天。

**关键设计原则**：AI 只做"翻译"与"编排"，绝不直接做数值计算。所有水文结果由确定性模型产出，每一条处置建议都必须能回溯到官方应急预案原文——在防汛场景，模型不容许编造。

**技术底座**：以 Dify 为编排平台，落地 LLMOps / RAG / Agent / AI Workflow 四类能力，形成可被企业直接采纳的 MVP。

## 四、现场完成内容

### 1. 可交互离线作品（单文件，零依赖）

`AquaPulse-离线完整版.html`（约 290 KB）——两个高质量移动端 Demo 已内联进同一文件，U 盘拷贝或邮件发送后双击即可运行，无需后端、无需联网。

- **四角色登录隔离**：水利气象指挥部、受灾村民、应急救援队、农业灾情统计员，各司其职、数据互通。
- **GIS 指挥调度大屏**：淹没范围、北斗短报文链路、安置点、救援力量、物资需求、活跃预警、底部「时光机」推演轴。
- **八步模型链自动推演**：进入页面即自动推进，每 1.6 秒点亮一步，参数修改自动重算，全程零点击。
- **AI 智能中枢**：山洪推演引擎、AI 智能派单、应急预案库、准确率评测四个页签，进入后自动动画演示运行全过程。
- **村民端 / 救援端**：完整手机端 Demo，含预警接收、避险登记、SOS 求救、安置点导航、任务接收与执行上报。
- **农业灾情统计端**：灾情登记、损失汇总。

### 2. Dify 编排工程（`dify/`）

- **4 个工作流 DSL**：八步山洪推演 / SOS 智能派单 Agent / 应急预案检索 / 灾后 AI 定损，可直接导入 Dify 复现。
- **3 套知识库语料**：防汛应急预案汇编、历史山洪灾情案例库、山洪滑坡避险指引。
- **LLMOps**：22 条评测用例 + 提示词版本管理 + 回归阻断机制（准确率下降超 1 个百分点自动阻止上线）。

### 3. 完整前后端源码（`11 AquaPulse/`）

React 18 + TypeScript + Vite 前端，Express + TypeScript + SQLite 后端，Leaflet GIS，WebSocket 实时通信，Docker / Vercel 部署配置。

## 五、使用方式

### 评委 / 普通用户：直接体验

1. 双击打开 `AquaPulse-离线完整版.html`（现代浏览器即可，推荐 Chrome / Edge）。
2. 用下方任一演示账号登录：

| 角色 | 用户名 | 密码 | 能看到什么 |
|------|--------|------|-----------|
| 水利气象指挥部 | `admin` | `admin123` | 指挥调度大屏、预警发布、AI 智能中枢、人员台账、救援调度、智能情报中心 |
| 辖区村民 | `villager1` | `123456` | 预警接收、避险登记、SOS 求救、安置点导航、亲属联系 |
| 应急救援队伍 | `rescue1` | `123456` | 任务列表、任务详情、执行上报、队伍状态 |
| 农业灾情统计员 | `agriculture` | `agri123` | 灾情登记、损失汇总统计 |

3. 建议体验路线：先 `admin` 登录看大屏 → 进「预警发布」看八步自动推演 → 进「AI 智能中枢」看四个页签自动演示 → 退出后用 `villager1` 与 `rescue1` 体验移动端。

### 企业落地：复现 AI 编排

1. 打开 Dify 平台（开源版或云端版均可）。
2. 依次导入 `dify/workflows/` 下的 4 个 YAML 文件。
3. 把 `dify/knowledge/` 下 3 份语料上传为知识库，在工作流的知识检索节点关联对应知识库。
4. 跑 `dify/llmops/评测集.csv` 做回归验证，通过后即可接入真实雨量与人口数据。

### 开发运行：完整前后端

```bash
cd "11 AquaPulse"
npm install
npm run dev      # 前端
cd api && npm run dev   # 后端
```
